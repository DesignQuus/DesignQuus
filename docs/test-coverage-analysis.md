## 테스트 인프라 구축을 위한 제안

### 1. 테스트 프레임워크 선택 및 설정

프로젝트 기술 스택(언어/프레임워크)을 먼저 결정한 후, 적합한 테스트 프레임워크를 도입해야 합니다.

| 언어 | 추천 프레임워크 | 비고 |
|------|----------------|------|
| JavaScript/TypeScript | Jest 또는 Vitest | Vitest는 Vite 기반 프로젝트에 최적 |
| Python | pytest | 풍부한 플러그인 생태계 |
| Go | 내장 testing 패키지 | 별도 설치 불필요 |
| Java | JUnit 5 | Spring 프로젝트와 통합 용이 |
| Rust | 내장 test 모듈 | cargo test로 실행 |

### 2. 프로젝트 기본 설정 파일 추가

- **패키지 관리**: `package.json`, `pyproject.toml` 등 프로젝트에 맞는 패키지 관리 설정
- **`.gitignore`**: 빌드 산출물, 의존성 폴더, 환경 파일 제외
- **린팅/포매팅**: ESLint, Prettier, flake8 등 코드 품질 도구 설정

### 3. CI/CD 파이프라인 구성

- `.github/workflows/`에 테스트 자동 실행 워크플로우 추가
- PR 생성 시 테스트 통과를 필수 조건(required check)으로 설정
- 커버리지 리포트 자동 생성 및 추적

예시 워크플로우 구조:

```yaml
# .github/workflows/test.yml
name: Tests
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Install dependencies
        run: # 패키지 매니저에 맞는 설치 명령어
      - name: Run tests
        run: # 테스트 실행 명령어
      - name: Upload coverage
        run: # 커버리지 리포트 업로드
```

### 4. 커버리지 목표 설정

- 코드 커버리지 도구 설정 (Istanbul/nyc, coverage.py, go cover 등)
- 최소 커버리지 임계값 설정 (권장: 80%)
- PR에 커버리지 리포트 자동 코멘트 구성 (Codecov, Coveralls 등)

### 5. 테스트 전략 수립

개발 시작과 함께 다음 세 가지 수준의 테스트를 계획해야 합니다:

#### 단위 테스트 (Unit Tests)
- 개별 함수/모듈의 핵심 로직 검증
- 외부 의존성은 mock/stub으로 대체
- 빠른 실행 속도 유지

#### 통합 테스트 (Integration Tests)
- 모듈 간 상호작용 검증
- 데이터베이스, API 등 외부 시스템과의 연동 테스트
- 실제 환경에 가까운 설정 사용

#### E2E 테스트 (End-to-End Tests)
- 사용자 시나리오 기반 전체 플로우 검증
- Playwright, Cypress 등 브라우저 자동화 도구 활용 (웹 프로젝트의 경우)
- 주요 사용자 경로(critical path) 중심으로 작성

### 6. 테스트 작성 원칙

CLAUDE.md에 명시된 원칙을 준수합니다:

- **Arrange-Act-Assert 패턴**: 테스트 데이터 준비 → 실행 → 결과 검증
- **의미 있는 커버리지**: 단순 높은 수치보다 핵심 로직 커버리지에 집중
- **구현 세부사항 테스트 지양**: 공개 인터페이스 및 동작 중심 테스트
- **회귀 테스트**: 버그 수정 시 해당 버그를 재현하는 테스트 우선 작성
